# シンプルCPU通信設定 バリデーション規則一覧

`scripts/generate_csv.py` が `generate` および `validate` 時に適用するチェック項目をすべて列挙する。
出典は MELSEC iQ-R Ethernetユーザーズマニュアル(応用編) 1.15節 (p.220-242)。
ページ番号はすべて同マニュアル準拠。

## 1. ヘッダー部

### 1.1 file_version
- 文字列。デフォルト `"1"`。GX Works3現行バージョンは `1` 固定。

### 1.2 title
- 任意の文字列。空欄 `""` 可。

### 1.3 target_unit
- 任意のCPU形名文字列（例 `R04CPU`, `R120CPU`, `R04ENCPU`）。
- フォーマット検証は行わない（フリー文字列として透過）。

### 1.4 local_ip
- IPv4ドット表記 `a.b.c.d`、または `ip_format=HEX` の場合は8桁hex（例 `C0A80327`）。
- 範囲: `0.0.0.1` ～ `223.255.255.254`（PDF p.222の交信相手側と同等）。
  - `0.0.0.0` ／ `224.x.x.x` 以上 ／ `255.255.255.255` は不可。
- マルチキャスト・ブロードキャストは拒否。

### 1.5 ip_format
- **`"DEC"` 固定**（iQ-Rプロジェクトの GUI で `IPアドレス入力形式` 欄が編集不可で 10進数固定のため）。
- HEX を指定するとバリデーションエラー。GX Works3 がインポート時に該当行をデフォルト値の空行に置き換えるため、無理に HEX で出してはいけない。

### 1.6 device_assignment
- `"Points/Start"` または `"Start/End"` のいずれか。
- どちらでもCSV上は点数・先頭・最終のすべてが書き出されるため、表示モードの違いだけ。

### 1.7 comm_start_wait
- 整数、`0` ～ `255`（秒）。

### 1.8 initial_comm
- `"Enable"` または `"Disable"` のいずれか。

## 2. 設定行（最大64件）

### 2.1 設定No.（`no`）
- 整数、`1` ～ `64`。
- ファイル全体で重複不可。

### 2.2 通信パターン（`pattern`）
- `"Read"` または `"Write"`。
- `Read`: 交信相手(転送元) → 自局(転送先) の方向。
- `Write`: 自局(転送元) → 交信相手(転送先) の方向。

### 2.3 交信設定（`schedule`）と実行間隔（`interval`）

| schedule | interval | 異常監視時間 |
|----------|----------|------|
| `"periodic"` (定期) | 必須。`10` ～ `65535` (ms) | 任意設定可 |
| `"request"` (要求時) | **省略必須**（CSV上は空欄） | **空欄必須** |

- 要求時に `interval` が指定されていればエラー。
- 要求時に `error_monitor_sec` が指定されていればエラー。

### 2.4 交信相手設定 (`target`)

#### 2.4.1 device_type
- 整数コード、または別名文字列で指定可。

| コード | 別名（受け付ける文字列） | 機器種別 |
|--------|-----------------------|---------|
| 16 | `"iQ-R"`, `"R"`, `"iQ-R-builtin"` | 三菱iQ-R(内蔵Ethernet) |
| 17 | `"Q"`, `"Q-builtin"` | 三菱Q(内蔵Ethernet) |
| 18 | `"L"`, `"L-builtin"` | 三菱L(内蔵Ethernet) |
| 19 | `"iQ-F"` | 三菱iQ-F(内蔵Ethernet) |
| 20 | `"iQ-L"` | 三菱iQ-L(内蔵Ethernet) |
| 22 | `"Q-EU"`, `"Q-Ethernet-Unit"` | 三菱Q(Ethernetユニット) |
| 23 | `"L-EU"`, `"L-Ethernet-Unit"` | 三菱L(Ethernetユニット) |
| 25 | `"A"`, `"AnS"`, `"A-AnS"` | 三菱A/AnS(Ethernetユニット) |
| 26 | `"FX3"` | 三菱FX3(Ethernetブロック・アダプタ) |
| 30 | `"SLMP"` | SLMP対応機器(QnA互換3Eフレーム) |

それ以外の数値・文字列は拒否。

#### 2.4.2 ip
- 1.4節の `local_ip` と同じ範囲で検証。

#### 2.4.3 tcp_udp
- 必ず `"UDP"`（シンプルCPU通信は UDP のみ対応）。

#### 2.4.4 port／local_port

PDF p.222の表に基づく。

| 機器種別 | port (交信相手側) | local_port (自局側) |
|---------|------------------|---------------------|
| 16, 17, 18, 19, 20, 22, 23 | **空欄必須** (設定不可) | **空欄必須** (設定不可) |
| 25 (A/AnS) | `256` ～ `65534` 必須 | `1`～`4999` または `5010`～`65534` 必須 |
| 26 (FX3) | `1025`～`5548` または `5552`～`65534` 必須 | `1`～`4999` または `5010`～`65534` 必須 |
| 30 (SLMP) | `1`～`4999` または `5010`～`65534` 必須 | `1`～`4999` または `5010`～`65534` 必須 |

注: PDF p.222 の表は `自局ポート番号` 列が A/AnS から SLMP までセル結合されており、3行とも同じ範囲を共有している。一方 `ポート番号` (相手側) は機器種別ごとに異なる。SLMP に対し `5000`～`5009` の port を指定すると GX Works3 のインポート時にエラーになる。

- "空欄必須" の機器種別で `port` または `local_port` が指定されているとエラー。
- "必須" の機器種別で空または範囲外だとエラー。
- `1024` 以下と `61440` 以上の `local_port` は推奨外（PDF p.222）だが、上表の範囲内であれば本スクリプトは通す。
- **`option_hex` (オプション(16進数)) は機器種別を問わず `""` 固定** ── iQ-Rプロジェクトでは GUI で編集不可。任意の値を指定するとエラー。値を含む CSV を GX Works3 がインポートすると該当行が破棄される。

#### 2.4.5 cpu_no（対象号機）
- 整数、`0` ～ `8`。`0` は「指定なし」。
- `1` ～ `8` はマルチCPUシステム時の号機指定。

### 2.5 ビットデバイス／ワードデバイス

#### 2.5.1 共通
- `bit_device` ／ `word_device` は両方省略可（少なくとも片方は通常設定する）。
- 設定する場合、`src` と `dst` の両方が必須。

#### 2.5.2 種別 (type)
- 機器種別（交信相手）と通信パターン（`pattern`）に応じて、許容デバイスが変わる。
- `pattern=Read` のとき、`src` 側は **交信相手** のデバイス、`dst` 側は **自局** のデバイス。
- `pattern=Write` のとき、`src` 側は **自局**、`dst` 側は **交信相手**。
- それぞれの側で `device_ranges.json` の `own_station` または `partner_devices[<code>]` を参照。
- `pattern_only` 制約のあるデバイス（タイマ／積算タイマ／カウンタの接点・コイル）は通信方向に応じて拒否される。

#### 2.5.3 先頭・最終 (start, end)
- ビットデバイス: 先頭は **0 または 16の倍数**（PDF p.224）。
- 最終 = 先頭 + 点数 − 1 と一致すること（不一致ならエラー）。
- 値は対応デバイスの基数（`base`）で解釈。文字列・整数いずれの入力も受付。
  - 例: `X` (base 16) なら `"F"` ／ `"0xF"` ／ `15` のいずれもOK。

#### 2.5.4 点数 (points)
- ビットデバイス: 16の倍数、`16` ～ `8192`。
- ワードデバイス: `1` ～ `512`。

#### 2.5.5 範囲チェック
- `start ≥ デバイスごとのmin` かつ `end ≤ デバイスごとのmax`。
- iQ-F の `D` は `0`～`7999` ／ FX3 の `M` は `0`～`7679` または `8000`～`8511` ／ A/AnS の `M` は `0`～`8191` または `9000`～`9255` のような特殊範囲も `partner_devices` に内包。
- A/AnS で書込時 (`Write`) `M9000-9255` ／ `D9000-9255` の場合、先頭は `9000+16k` の制約あり（PDF p.228）。

### 2.6 1設定あたりの合計点数

- ビット n 点を `n/16` ワード換算し、ワード m 点と合計したものが
  `1設定あたり ≤ 512 ワード`（PDF p.224）。
- 超過するとエラー。

### 2.7 ファイル全体合計

- 全 `settings[]` のワード換算合計が `≤ 8192 ワード`（PDF p.224）。
- 超過するとエラー。

### 2.8 通信タイムアウト時間 / 通信リトライ回数 / 異常監視時間
- `timeout_ms`: 整数。範囲チェックは緩い（`0` 以上）。GX Works3 デフォルト `1000`。
- `retry_count`: 整数 `0` 以上。デフォルト `3`。
- `error_monitor_sec`: 2.3節参照。periodic 時のみ意味を持つ。

### 2.9 コメント
- 任意文字列。空欄可。

## 3. 厳守事項（ハードフェイル）

以下のいずれかに該当した場合は CSV を生成せず、エラーで終了する:

1. 必須キー欠落（pattern, schedule, target.device_type, target.ip など）
2. デバイス種別が機器種別の許容リストに無い
3. デバイス番号が `min`～`max` 範囲外
4. ビット先頭が16の倍数でない
5. 点数 = (end - start + 1) と矛盾
6. ポート要件違反（forbidden 機器種別での指定 ／ 必須機器種別での欠落）
7. 設定No. 重複 ／ 65以上
8. 1設定 / 全体の点数上限超過
9. periodic で interval 欠落
10. request で interval または error_monitor_sec が指定されている
11. 通信パターンによって禁止される `pattern_only` デバイスの指定
   （例: 自局TS／TC を `pattern=Read` で指定 — TS/TC等は自局側では Write 時のみ）
   （例: 交信相手TS／TC を `pattern=Write` で指定 — Read 時のみ）

## 4. ソフトチェック（警告ではなく通す）

- 自局CPUの形名と `own_station` の最大範囲の照合（実機の点数設定パラメータに従うべきだが、本スクリプトでは R120CPU + NZ2MC-16MBS の最大値で許容判定する）
- ローカルポート番号の推奨外帯域（`1`～`1023`, `61440`～`65534` の WELL KNOWN PORT 帯）
- リモートパスワード設定の有無（PDF p.241 — 設定されている場合は実行不可だがCSVには現れない）
