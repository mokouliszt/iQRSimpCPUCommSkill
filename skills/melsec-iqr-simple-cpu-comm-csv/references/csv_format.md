# シンプルCPU通信設定 CSV フォーマット仕様

GX Works3 が "シンプルCPU通信設定" 画面でインポート／エクスポートするCSVの仕様。
出典: MELSEC iQ-R Ethernetユーザーズマニュアル(応用編) 1.15節 (p.220-242, 特にp.230のフォーマット表)。

## ファイルエンコード

| 項目 | 値 |
|------|---|
| 文字コード | UTF-16 Little Endian + BOM (`FF FE`) |
| フィールド区切り | タブ (`\t`) |
| 行区切り | CRLF (`\r\n`) |
| 各セル | ダブルクォート `"..."` で囲む |
| セル内のダブルクォートのエスケープ | `""` (2連) |

エクスポートされたCSVを直接エディタで編集する場合、上記すべてを保つ必要がある。

## 行構造

1～8行目はヘッダー、9行目はカラム見出し、10行目以降が設定データ（最大64件 = 行73まで）。

### 行1: ファイルバージョン

```
"ファイルバージョン"	"1"
```

`1` で固定（現行GX Works3）。

### 行2: ラベル／タイトル（単一フィールド）

```
"test"
```

このスキルでは `header.title` として保持する。サンプルでは `"test"` だが、空文字 `""` でも動作する想定。
他のヘッダー行と異なり key/value の2列ではなく **1セルだけ** な点に注意。

### 行3: 対象ユニット

```
"対象ユニット"	"R04CPU"
```

例: `R00CPU`, `R01CPU`, `R04CPU`, `R08CPU`, `R16CPU`, `R32CPU`, `R120CPU`, `R04ENCPU`, `R08PCPU` など。
スクリプトでは型までは検証しない（フリー文字列として通す）。

### 行4: 自局IPアドレス

```
"自局IPアドレス"	"192.168.3.39"
```

行5の `IPアドレス入力形式` が `DEC` ならドット表記、`HEX` なら8桁の大文字hex（例 `C0A80327`）。

### 行5: IPアドレス入力形式

```
"IPアドレス入力形式"	"DEC"
```

**iQ-R プロジェクトでは `DEC` 固定**。GX Works3 のシンプルCPU通信設定画面では `IPアドレス入力形式` 欄が編集不可（グレーアウト）になっており、10進数しか選べない。
HEX を CSV に書くと **GX Works3 がインポート時に該当行を破棄してデフォルト値の空行に置き換える**。本スクリプトは `DEC` 以外を指定するとバリデーションエラーで停止する。

### 行6: デバイス割付方法

```
"デバイス割付方法"	"Start/End"
```

`Points/Start` または `Start/End`。GUI上の「点数/先頭」と「先頭/最終」の選択に対応する。
CSV上は **常に 点数・先頭・最終 のすべてが書き出される** ため、両モードで読み出しは共通。
書き出し時のみ意味を持つ（GUIに戻った時の表示モード）。

### 行7: 通信開始待ち時間

```
"通信開始待ち時間"	"0"
```

整数（秒）。範囲: `0` ～ `255`。

### 行8: 初回交信設定

```
"初回交信設定"	"Enable"
```

`Enable` または `Disable`。

### 行9: カラム見出し

29カラム固定。順序は **scripts/generate_csv.py の `COLUMN_HEADERS` 定数と一致** している必要がある。

```
設定No.  通信パターン  交信設定  実行間隔
交信相手設定：機器種別  交信相手設定：IPアドレス  交信相手設定：TCP/UDP
交信相手設定：ポート番号  交信相手設定：自局ポート番号  交信相手設定：オプション(16進数)
対象号機
ビットデバイス：点数  ビットデバイス：転送元種別  ビットデバイス：転送元先頭  ビットデバイス：転送元最終
              ビットデバイス：転送先種別  ビットデバイス：転送先先頭  ビットデバイス：転送先最終
ワードデバイス：点数  ワードデバイス：転送元種別  ワードデバイス：転送元先頭  ワードデバイス：転送元最終
              ワードデバイス：転送先種別  ワードデバイス：転送先先頭  ワードデバイス：転送先最終
通信タイムアウト時間  通信リトライ回数  異常監視時間
コメント
```

注: PDF本文では `異常時監視時間` と表記されるが、CSVカラム名は `異常監視時間`（"時"なし）。

### 行10～: 設定データ

各行が1件の設定（最大64件）。空欄は `""`。

| | 三菱iQ-L(内蔵Ethernet) | `20` |

## デバイス番号の表記基数

ビット／ワードデバイスの先頭・最終はそれぞれのデバイスが持つ表記基数で書き出される。

| デバイス | 基数 | 例 |
|---------|------|---|
| X, Y (iQ-R) | 16進数 | `00000`, `0000F`, `00010`, ... |
| X, Y (iQ-F/FX3) | 8進数 | `0`, `7`, `10`, `377`, ... |
| B, SB | 16進数 | `0`, `FFF`, ... |
| W, SW | 16進数 | `0`, `FFFF`, ... |
| M, L, F, D, R, ZR, RD, T*, C*, ST*, SM, SD | 10進数 | `0`, `4095`, ... |

GX Works3エクスポート時、X/Y(16進)は5桁ゼロパディング (`00000` 形式) で書き出されるが、
他デバイスは最小桁数（パディングなし）。本スクリプトもこれを踏襲する。

## ビットデバイスの先頭番号

PDF p.224の制約: **ビットデバイスのデバイス番号は 0 または 16の倍数 で指定する。**
たとえば `M0`, `M16`, `M32`, ... は OK だが `M5` は NG。
点数も常に 16の倍数（最小16点、最大8192点）。

## 1設定あたり／全設定合計の点数上限

- 1設定: 最大512ワード（ビット 8192点 ＋ ワード512点をワード換算で合計したもの）
- ファイル全体: 設定No.1～64の合計で 8192ワード

ビット n 点 = n/16 ワードとして合算する。

## 異常監視時間

`交信設定` が `1`(定期) の場合のみ意味を持つ。`0`(要求時) のときは空欄 `""`。

## "test" の正体について

PDF本文には行2のラベル単体フィールドの意味は明記されていない。
GX Works3 のエクスポート時に固定文字列 `"test"` が出力されるわけではないが、
インポートが失敗するわけでもないため、本スキルでは `header.title` として透過保持する。
不明な場合は空文字列 `""` を入れておけばよい。
